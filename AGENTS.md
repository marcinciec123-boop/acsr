- Render trophy artwork from one 4×4 generated sprite atlas with a deterministic tournament-name variant, so the same event always has the same trophy in player and team profiles without sixteen separate downloads.
- Tournament match previews share MatchHoverPreview and render through a portal using only supplied match data, avoiding clipped popups and extra save scans or writes.
- In-app Back uses sessionNavigation snapshots owned by Index (panel, profile and tournament identifiers plus scroll); TournamentPanel receives controlled selection, keeping navigation history out of game saves and avoiding deep-link event races.
- Derive cabinet entries from each save's existing tournament placements and player career participation; never persist duplicate trophy awards, so imported saves appear automatically.

- Desktop app is a Tauri v2 shell in src-tauri bundling the built dist offline; GitHub Actions builds a signed release on every push to main and the in-app updater pulls latest.json, since the sandbox cannot produce .exe files.
- Desktop release builds use tauri-action's bounded retryAttempts for transient installer-tool download failures, without bypassing signing or publishing failed builds.
- Keep src-tauri/Cargo.lock committed and pin withdrawn (yanked) transitive crates through [patch.crates-io] in src-tauri/Cargo.toml, so CI dependency resolution keeps working when crates.io pulls a version.
- Pin @tauri-apps/* npm plugin packages to the same major/minor as their matching Rust crates in src-tauri/Cargo.lock, because the Tauri CLI aborts the build when an npm package and its crate differ on major/minor.
- Bracket views derive match positions and connector paths through the shared graph-based bracket layout helper, so irregular lower-bracket rounds remain aligned across tournament and group views.
- All disband and manual bankruptcy actions use `disbandTeam` to capture members before removal, clear current roster/coach overrides, release organization contracts and move members to free agency; this prevents orphaned players and continuing payroll without rewriting historical transfers.
- Change-log snapshots deep-copy contracts, bench membership/history and finance inputs; restoration skips fields absent from legacy snapshots and notifies domain subscribers after writes, so undo reverses transfer accounting without erasing uncaptured data.
- Backup restoration treats tournament logos as device media and broadcasts a global logo update that clears the tournament-logo memo; this preserves small images and refreshes previously cached images or missing results.
- File exports encode compact snapshots through native Gzip streams and imports detect Gzip magic bytes, retaining legacy JSON support; media exclusion only filters the exported copy so on-device snapshots remain complete.
- All uploaded team/tournament logos and player photos pass through the shared fileToLogoDataUrl resize/encoding helper, preserving alpha and avoiding upscaling or enlarging small raster uploads.
- Accolade lookups and organization earnings use canonical team identity and normalized comparisons; historical award and tournament records stay unchanged so renames preserve history without splitting totals.
- Bench reads merge all aliases of a club and bench mutations replace those aliases together; normalized player matching prevents stale bench entries from reactivating players in the simulator.
- Statistics memoization tracks rename-log changes as well as tournament/ranking data; profile earnings use that cache directly to avoid stale totals in a second cache.
- Automatic lineups exclude bench members even when every player is benched; explicit tournament lineups may still select a substitute intentionally.
- Series outcomes, progress, advancement and completed-match history use the shared matchStatus helpers; partial map results are saved atomically with map-win totals so leaving a match cannot finalize a series early.
- Ranking tier labels use the shared rankingTier helper and the table renders the complete eligible club list; this keeps profiles and ranking consistent without a fixed club-count cap.
- Ranking position charts derive their axis from displayed history via rankingScale; this keeps low-ranked clubs visible as the database grows.
- In the Tauri build, deviceStore persists every key as its own atomically-written file in AppData via Rust commands (store_load_all/store_write/store_remove) with debounced writes; browser IndexedDB stays as a mirror and the web preview fallback, so saves are no longer bound by webview storage quotas.
- On disk, tournaments_data is sharded into per-year files plus an id-order file (diskStore shardList/joinShards), rewriting only changed years; lists with duplicate ids fall back to one file so no tournament is collapsed.
- Team ranking series come from a per-history-identity index in rankingHistory, and trend charts drop unchanged middle points via compactSteps, keeping long histories cheap without altering data.
- In the Tauri build, team/tournament logos and player photos are stored as binary image files in AppData/media (Rust media_* commands), loaded on demand through a small in-memory LRU and excluded from the startup cache; backups and resets read them via getAllDeviceValuesWithMedia, so image count does not grow RAM use.
- Bracket round grouping, side detection (slot first, round name fallback), decider/Grand Final ordering, adding and moving rounds go through src/lib/bracketRounds.ts, so new rounds insert next to their side instead of at the end of the list.
- Loading tournaments_data merges neighbouring "Group X"/"Grupa X" phases (same group format and BO) into one group-stage phase via mergeGroupPhases, so imported historical events show groups inside one phase.
- Historical seeders only add a tournament when its id is missing and never replace an existing copy, so player edits survive seed version bumps.
- Disk write queue keeps failed writes for retry and serializes flushes; restore/reset await diskFlush before reload so the .exe never restarts on half-written files.
- Native save files use lossless Gzip when smaller, detected by magic bytes with legacy UTF-8 support; compress before atomic replacement and reject unreadable files instead of silently dropping keys. Current-world export collects live values after pending disk/media writes, while historical snapshot downloads stay historical.
- National-team identity goes through src/lib/nationalIdentity.ts (persisted name registry + isNational flag + Worlds kind); club systems (transfers, VRS, finances, bench, disband, invites, awards, records) filter with it, so renamed or removed national teams never leak into club data.
- News templates return unpublished drafts; shared news helpers handle editorial persistence, duplicate detection, commenter sampling and AI error messages so all entry points follow the same rules.
- Generated comment replies resolve by replyToAuthor before filtering, with original-batch indices only for legacy responses, so removed comments cannot shift reply targets.
- Match statistics map selectors use matchStatsMaps for read-only selection of played maps; the same totals tables render the aggregate or a single map without altering saved match data.
- MatchDetailPage edits results in isolated per-match drafts; only explicit confirmation publishes results, propagates advancement and replaces ranking awards. Date/BO metadata persists independently without propagation; draft restoration ignores metadata-only base changes and overlays current metadata, preserving unconfirmed statistics.
